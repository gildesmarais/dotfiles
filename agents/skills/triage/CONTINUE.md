Use this when continuing or refining the global `triage` skill (playbooks, ledger, README/CONTEXT wiring)—**not** when running intake on an app incident.

**How:** paste the prompt below as a single user message in a new agent session. Let the agent discover the continuation goal if unclear, then edit only triage-related store paths.

## Genesis

Born from an html2rss scrape/Sentry session: fail-closed UX plus challenge-before-timeout. A long grill produced Intent intake so Shot 1 stays one–two messages. The Doc-class rename in `CONTEXT.md` freed the `triage` noun for this skill.

Evidence → Triage Ledger → `product-owner` gate and/or `$dev` plan only. No Build inside triage. Playbooks load progressively under `reference/`, not as peer branches. Keep `/triage` / `/intake` discoverable.

Intent domain. Compose: incident/observability without Jira or IR → `triage` first (store README rule 1). Handoff matrix lives in `SKILL.md`. Never owns Assure or Ship.
