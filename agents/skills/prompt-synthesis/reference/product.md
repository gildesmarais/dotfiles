# Product branch rubric

Enrich the five-field brief for scope, UX/mental model, or feature-shape intent. Do not invent a parallel template.

## Fold into Context

- User outcome in plain language (who benefits, what changes in their path).
- Current product state vs desired state when known from the user or repo product docs.
- Golden path / click pressure / mental model **only if grounded** in repo product docs (`AGENTS.md`, `ROADMAP.md`, or equivalents). If docs are silent, do not invent budgets — grill or mark Unknown on escape.

## Fold into Constraints

- Exclusions: out-of-scope personas, surfaces, or “nice to have” expansions.
- Non-negotiables from grounded product docs only.
- Explicit deferrals the user already decided.

Omit Constraints if none of the above exist.

## Fold into Verify

- Observable acceptance signal (user can complete X in Y steps; screen/API shows Z).
- Do not invent click budgets, OKRs, or metrics absent from repo docs or the user’s answers.
- Keep Success as the outcome; Verify as how a reviewer confirms it without implementing here.
