# Growth (branch expansion + harvest)

Load only when adding an architecture branch or harvesting lessons.

## Branch expansion law

1. Refactor branches are only `refactor-<concern>` (e.g. `refactor-types`); never `refactor`, `refactor-misc`, `cleanup`, or language-named (`refactor-rust`).
2. New branch only if all hold: distinct signals; cannot be a section of an existing `reference/*.md`; reusable ≥2 times; language-free. Reject third-party recipe dumps and craft branches duplicating survey discovery.
3. Adding one = one `## Pick branch` row + `reference/<branch>.md` with `## Done when`; never a new top-level skill. Discovery modes feeding craft branches may be a `reference/*.md` + router contract without becoming a craft branch.
4. Overlap (primary branch): tree / peer-layout / snowflake → `structure-survey`; ownership/depth → `deep-modules`; type dual homes → `refactor-types`; serialize/layer shells → `refactor-boundaries`; measured speed/alloc → `performance`; named GoF / which-pattern → `design-patterns`.
5. Growth default: stage in [`learning-log.md`](learning-log.md) → **sparse-promote** into the matching `reference/<branch>.md` Checklist or Anti-patterns only when judgment changes and neither that file nor [`glossary.md`](glossary.md) covers it → **drop** the rest. Edit the router (`SKILL.md`) only when the contract is wrong.

## Harvest

Stage when a design or recurring failure class left a lesson that prevents the next dual-ownership / shallow-seam / type / measured-perf mistake, guidance was missing or wrong, or the user asks. Keepers are **preventive mantras** for failure classes — not incident write-ups or technique recipes.

1. Corpus = structural cuts (ownership, seams, types, measured perf); dependency bumps and fixture moves are not harvest. Repeated harden / review-follow-up chains may signal a missing principle.
2. Generalize before ingress: strip product nouns, paths, schemas, language APIs — a stranger must not infer the source codebase. One imperative sentence applicable in any language.
3. Drop restatements of checklist / anti-pattern / glossary lines and near-clones (a narrower failure class may specialize). Dropping weak harvests is required; no archive of rejects.
4. Tag one primary branch (overlap rule 4); other tags become co-load cues inside the bullet — no duplicate copies. Survey lessons go to `structure-survey.md` or glossary, never a new craft branch.
5. Cap ~10 candidates per harvest event unless asked; noise-pass for product leakage.
6. Write only from a fresh read of `learning-log.md` (concurrent shared state); promote or drop within the same event and leave the log thin.
