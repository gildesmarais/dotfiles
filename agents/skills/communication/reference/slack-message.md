# Slack Message

Notes or a rough draft → Slack-ready internal message for mixed technical and non-technical audiences.

## Output

- Short paragraphs, bullets, light headings. Calm, deliberate, professional. Keep the user's intent, ask, and audience unless asked to reposition.
- Flow: intent → changes → audience impact → action; compress short announcements.
- Lead with why; name the accountable role. Translate mechanisms into audience consequences; keep mechanics only for scope, confidence, or required action.
- Frame standards, governance, capacity, compliance, or ops changes as delivery predictability, sustainability, risk reduction, quality, or customer outcomes.
- Predictable objection (friction, delay): evidence beside the change — bounded scope, what does not happen, practical benefit. No absolutes.
- Security or operational risk: consequence + completed mitigation; omit sensitive detail that does not aid action.
- Enablement (tools, AI, context): capability, workflows, quality/velocity outcome — not generic "use X".
- CTA: affected role, concrete action, timing when material, low-friction feedback path.

## Sensitive messages

Line managers, leadership, escalations, blockers, policy friction:

- Open with context and operational intent, not "We have a problem with…" / "You need to…". Frame it as a delivery, coordination, policy, or operational constraint before any team or role (system-first); name the consequence before any failure.
- Ask for alignment, confirmation, or a decision, not a directive, unless one is wanted.
- Pair the ask with why it matters in consequence phrasing ("Without this decision, we risk…"), not status. Direct attribution only when asked.

## Decision requests

Blocker needing leadership action: decision needed first → 2–5 compact progress bullets → blocker in operational terms → options only if in the user's input → consequence of delay + soft in-thread reply request.
